# 桌面端构建与验收

在 Windows 测试虚拟机中，从项目根目录构建并启动桌面端。

```console
cargo run --locked --release -p uninstallany-gui
```

首次开发构建需要下载 Rust 依赖。
构建后的程序从本机读取应用信息与字体，离线完成扫描、评审和恢复。

## 常用操作

1. 在应用列表中搜索应用名或发行商。点击列标题切换名称、大小、安装日期和发行商排序。
   系统组件默认隐藏，可以手动显示。列表中的大小、日期可能缺失。
2. 选择一个应用或输入便携目录，再启动扫描。按类别查看清单、置信度、风险和命中理由。
   只有高置信度、普通风险且可写的项默认勾选。核对只读和高风险项的选择行为。
3. 勾选一项或多项应用，再审阅官方卸载操作。确认后顺序执行，单项失败应保留在结果中。
   官方卸载完成且可核实时自动生成残留预览。选择预览中的目标，另行确认隔离或备份变更。
   执行前会重新扫描归属。预览后出现其他所有者或更严格的风险判定时，对应目标应被跳过。
4. 官方卸载入口失效时，查看强制移除预览与额外风险提示。
   只处理可证明归属的残留与可写的第三方卸载项。
5. 在隔离区选择要恢复的批次，确认还原范围并检查每项结果。
   占用原位置的测试文件或值应保持原样。
6. 在设置中切换显示语言或修改新备份的保留期。
   重启后核对保留期设置。已有备份保留创建时记录的到期时间。
7. 在设置中粘贴[自定义规则](custom-rules.md)，保存后重启，再扫描规则对应的测试应用。
   自定义规则提供只读线索。格式错误的规则应显示原因，并保留之前保存的版本。
8. 打开设置中的「操作日志」，在已有的本地目录填写一个新文件的绝对路径，再点击「导出日志」。
   对同一路径再次导出应提示文件已存在，并保留第一次生成的内容。
9. 在测试环境中把保留期设为一天，隔离一个可丢弃的测试文件并等待到期。
   到期后先确认它仍可还原，再在隔离区点击「检查到期文件」。
   清单默认不勾选。取消应保留文件，逐项勾选并确认后应记录「已永久清理」。
   同时核对未到期项、目录、应用包和注册表备份仍保留。

## 操作日志格式

导出使用 UTF-8 JSON Lines，每行一条记录，按 `time_unix_ms` 从早到晚排列。
`record_kind` 标识普通事件、清理回执、还原回执或到期清理回执，取值为 `event`、`applied`、`restored` 或 `purged`。
结合 `record_kind` 和 `record_id` 可区分记录。记录还包含 `batch_id`、`operation_id`、`object`、`action`、`result` 和 `backup`。

结果字段使用状态和错误码。旧版本的自由格式诊断以 `details_omitted` 替代。
检查清理和还原回执是否包含关联的操作 ID 与备份位置。
导出文件可能包含本机应用名称、文件路径和注册表项名称，共享前先检查内容。

## 桌面与 Windows 验收

- 验证初次加载、空列表、筛选、排序、批量勾选和显示系统组件。在小窗口中检查长名称与中文布局。
- 核对应用是否能在枚举和扫描时继续重绘，点击取消后不启动新任务。
  厂商卸载程序一旦启动，由它自己处理取消和完成，桌面端可取消的是之后的队列工作。
- 在 [Windows MVP 验证](windows-mvp-verification.md) 的测试快照中，运行原生夹具和人工冒烟。
  Windows GUI 的实际操作需覆盖预览、确认、同一任务内的清理结果和可冲突还原。
- macOS 和 Linux 的应用来源、原生卸载及隔离检查见 [Unix 后端验收](unix-backend-verification.md)。
- 从离线发行包验收时，使用[打包与核验流程](release-packaging.md)生成归档并检查 SHA-256。
- 在阶段一指定的 Windows 环境复测发布体积、空闲内存和冷启动。
  macOS 或 Linux 的前端构建和界面测试不能验证 Windows 原生操作或性能。
